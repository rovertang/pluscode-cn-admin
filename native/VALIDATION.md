# 构建与验证记录

## 二进制产物

| 平台 | SO 字节数 | 动态依赖 | ELF LOAD 段对齐 |
| --- | ---: | --- | --- |
| Linux x86_64 | 2,131,208 | glibc 系统库；最高 GLIBC 符号版本 2.28 | 4,096 |
| Android arm64-v8a | 1,827,808 | libc.so、libm.so、libdl.so | 16,384 |
| Android x86_64 | 1,850,720 | libc.so、libm.so、libdl.so | 16,384 |
| Android armeabi-v7a | 1,235,344 | libc.so、libm.so、libdl.so | 16,384 |

每个 SO 都核对了全部 11 个 C ABI 与 8 个 JNI 导出符号。SQLite、XZ、zlib、OLC 和 C++ 运行时均不需要另外提供动态库。交付库已去除调试符号，源码和构建方式保留。

JAR 包含 `PlusCodeIndex`、`Admin`、`Result` 三个 class，字节码主版本均为 52（Java 8），并包含 R8/ProGuard 保留规则。结构检查、SHA-256 和完整系统依赖见 `../validation/native/binaries.json`。

## 构建环境

- CMake 3.31.8；Linux 便携构建使用 Zig 0.14.1，目标 `x86_64-linux-gnu.2.28`。
- Android 使用 NDK r29，API 21，`c++_static`。
- JAR 使用 Temurin JDK 21.0.12.1 的 `javac --release 8`；Kotlin 示例使用 Kotlin 2.2.20、JVM target 1.8。
- 依赖版本与源码包 SHA-256 固定在 `source/dependencies.lock.json`。系统版本和实际执行的 Java 版本记录在 `../validation/native/runtime.json`。

## 对上游编码器的兼容修正

沿用 Google OLC C++ 编码实现，不重新实现字符编码或网格树规则。固定版本的上游代码存在两处需要与现有 V2 Python 语义对齐的行为：

1. 恰好 -180° 的经度在归一化整数为 0 时被错误地映射到 +180°。构建副本将相关条件从 `<= 0` 改为 `< 0`。
2. 原 C++ 实现先乘坐标再加偏移，直接取 floor；Python 参考实现先加坐标偏移，再乘精度并 round 到 6 位小数后截断。在网格线附近，两者可能得到相邻格。构建副本使用 `src/olc_quantize.hpp` 对齐这一步。

修正记录在 `cmake/dependencies.cmake`，保留原始上游源码压缩包不变。若未来依赖版本变化导致修正不再匹配，CMake 会报错。回归样本包含 2,000 个最细网格线交点及各点两侧，共 6,000 个坐标；另检查极点、日期变更线及其邻近位置。

## 验证范围

- C++/C ABI：省市县、粗码歧义、长码、越界参数、缓存上限、热命中、清缓存、关闭句柄和 800 次多线程查询。
- Java/JNI：类型化结果、缺失层级、完整 JSON、BMP 和补充 Unicode 字符、非法输入、I/O 异常、重复关闭、1,000 次多线程查询，并启用 `-Xcheck:jni`。
- Kotlin：实际编译并运行示例，通过 JAR/JNI 查询北京与粗码歧义案例。
- 对外链接：独立使用 GCC 编译 C++ 客户端和 C 客户端，链接已交付 Linux SO；不依赖库内部的 libc++ ABI。
- 额外的 ASan/UBSan 构建：查询引擎、C ABI、OLC 和原生测试启用地址/未定义行为检测并通过，包含 800 次多线程查询和泄漏检测。该附加构建中的 C 依赖及 JNI 未插桩；见 `../validation/native/sanitizers.json`。
- 全国差分：逐个访问全国混合块的固定查询样本，并补充随机坐标、不同码长、网格线与合成异常索引；统计见 `../validation/native/differential.json`。
- 内存：独立 C++ 进程依次执行启动、10,000 次热查询、2,000 次连续移动、邻域预热、3,000 次中国范围随机查询和清缓存。原始记录为 `../validation/native/memory.jsonl`。

差分验证是 Native 与既有 Python V2 的结果对照，不能替代原始行政边界数据本身的准确性验证，也不是枚举全国所有最细网格。首次访问每块时 Native 会扫描验证该块编码结构；查询结果只对所列采样点逐字段比对。

## 实测结果

全国 **92,174 个混合块**全部完成抽样查询和加载时的编码检查，**105,039 次 JSON 逐字段对照全部一致**，包括 **6,000 个网格线样本**。7 类异常索引（未完成、格式错误、缺块、坏 XZ、未知行政区 ID、坏子树长度、坏目录）均被正确拒绝。该轮差分耗时约 480 秒，报告绑定了数据库与实际测试 SO 的 SHA-256。

C++/C、Java/JNI、Kotlin、外部 GCC 客户端和额外 ASan/UBSan 检查均通过。实际宿主为 WSL2 / Linux 6.18.33.2 / glibc 2.43，JVM 为 Temurin 21.0.12.1。

使用默认 64 块/8 MiB 配置的独立 C++ 进程，结果如下。RSS 为整个测试进程的采样值，不是 Java 堆或 Android APP 的占用：

| 阶段 | 当前 RSS (KiB) | 已缓存块数 | 解压块缓存字节 | 该阶段耗时 (ms) |
| --- | ---: | ---: | ---: | ---: |
| 打开前 | 2,708 | 0 | 0 | - |
| 打开全国数据库 | 14,400 | 0 | 0 | 106.289 |
| 相同边界码查询 10,000 次 | 14,632 | 1 | 20,818 | 170.430 |
| 连续移动查询 2,000 次 | 14,868 | 9 | 216,636 | 66.701 |
| 半径 10 格、最多 64 块预热 | 16,328 | 64 | 1,558,146 | 162.601 |
| 中国范围随机查询 3,000 次 | 16,480 | 64 | 1,106,270 | 1,144.200 |
| 清缓存后 | 15,832 | 0 | 0 | - |

启动时混合块加载数和读取的混合 BLOB 字节数都为 0，常驻目录 3,213 条、字典 2,853 条。10,000 次同码查询只加载 1 块，其余 9,999 次命中。完成全部场景共加载 398 次，累计读取压缩 BLOB 871,932 字节，发生 334 次 LRU 淘汰；随机点也通过逐块按需读取完成。

这里最高记录 RSS 为 16,480 KiB，约 **16.09 MiB**；不是内存硬上限，也不是 Android 设备性能保证。原始报告同时保留 `/proc/self/status` 和 `getrusage` 两种采样，它们的计数/采样时机不同，不宜把数值相减来解释某次分配。清缓存后 RSS 未回到启动前，符合字典常驻及分配器可能保留已释放空间的行为。

测试运行在全国差分扫描之后，OS 文件缓存可能已预热；没有清空系统磁盘缓存。移动轨迹和随机样本是合成数据，随机查询还包括目录直接命中及未覆盖位置。上述耗时包含完整 JSON 结果生成，不能当作设备端冷 I/O、真实车辆流量或全国生产吞吐承诺。

## 当前限制

没有连接 Android 真机或模拟器，因此未执行 Android/ART、设备端内存、release APK 压缩和 16 KiB 设备运行测试。已完成的是三种 Android ABI 的交叉编译和 ELF/导出/依赖检查，以及同一 JNI 源码在 Linux JVM 上的实际运行。接入 APP 后仍需在目标设备上验收最终 APK。

Linux 测试在当前 WSL 发行版运行；glibc 2.28 兼容下限来自构建目标与 ELF 符号检查，没有在 glibc 2.28 的旧发行版上启动运行。Java 8 兼容性来自字节码目标与 API 约束，实际 JVM 验证使用 JDK 21。

编译中仍可见上游 OLC 解码函数的整数转换警告、标准库 `codecvt` 在 C++17 中的弃用提示，以及 JDK 对 Java 8 目标的旧版本提示；这些不是构建失败。工程固定为 C++17，未来升级到删除 `codecvt` 的标准版本时需要替换 JNI 字符串转换实现。
